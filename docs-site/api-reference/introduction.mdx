The `/v1` API lets you drive any agent programmatically. It's the same engine as
the console, exposed for your own integrations.

## Base URL

```
https://app.over-watch.in
```

<Note>
  The base URL moves to the `antonagents.com` domain after the domain cutover.
  Existing links keep working until then.
</Note>

## Authentication

Every request uses an **agent-scoped API key** as a bearer token:

```
Authorization: Bearer sk_ag_...
```

- Create keys in the console on an agent's **API** panel (shown once, copy it).
- A key is scoped to **one agent** and can be revoked/rotated any time.
- JSON endpoints also require `Content-Type: application/json`.

## The shape of a call

Agent calls are **runs**: you start one, then get its result in whichever way
suits your integration.

<Steps>
  <Step title="Start a run">
    `POST /v1/agents/{public_id}/chat` (send a message) or
    `POST /v1/agents/{public_id}/run` (use the agent's default instruction).
    Returns a `run_id`.
  </Step>
  <Step title="Get the result">
    - **Wait:** add `?wait=N` to the call above to block up to `N` seconds and get
      the result in the same response (`done: false` if it's still running).
    - **Poll:** `GET /v1/runs/{run_id}?public_id={public_id}` until its status is
      terminal (`succeeded`, `failed`, `interrupted`).
    - **Stream:** `GET /v1/runs/{run_id}/stream?public_id={public_id}` for live
      server-sent events.
  </Step>
</Steps>

Every agent is also an **MCP server** at `POST /v1/agents/{public_id}/mcp`, using
the same key. See [Agents as MCP servers](/guides/mcp-server).

## Rate limiting

Each key is limited by a token bucket (sustained requests per minute with a
burst). Over the limit returns **429** with a `Retry-After` header.
